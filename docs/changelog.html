v3.0.0
首个对外版本：适配 foo_ui_webview2 2.0.0；双轨制播放模型（插队队列 + 播放历史）+ 入口重排 + 「设置与工具」页 + 频谱与小窗修复
播放模型重构：双轨制（插队队列）+ 播放历史 + 移除试听

右侧那块列表此前的定位是模糊的：它既是"下一首播放"的落点，又和"双击播放"混在一起，用户很难说清"播完插队歌之后会播什么"。这一版把它收成一套明确的双轨制模型，并把"试听"这条并行的播放链路整条删掉。

  • 右侧 = 插队队列（foobar 原生播放队列）：改名（原「播放队列」→「插队队列」，底栏按钮提示与抽屉标题同步）、空态写明「当前无插队歌曲，将按中间列表顺序播放」—— 这句话回答的正是"为什么播完插队歌没回到我原来的歌单"。队列的"优先级最高、播完一首移一首、播完回到上下文当前游标"全部由宿主原生保证，主题只做两处显式动作：手动「下一首」先播队首（queue.playNow，老宿主退回 playback.next），以及切换上下文时 queue.clear（只清待播项，不打断当前曲）。
  • 中间大列表 = 播放上下文（活动播放列表）：双击歌单行 / 库页行 / 搜索结果 = 切换上下文并清空插队队列，通过 playlist.setActive + playlist.playTrack 完成；活动歌单已经是它时跳过 setActive（否则每次播放都会触发一次整表重载）。
  • 媒体库 / 发现 / 搜索是"视图"而不是歌单：新增 js/playback-model.js —— 播放时把当前视图的完整曲目映射进专用歌单 _MediaLibraryContext_（playlist.create + playlist.replaceAllAndPlay，一次调用完成"停 → 清 → 加 → 激活 → 定位播放"），并在 Web 层按"标题 + 长度 + 首尾路径"记签名：同一份视图里再点另一首只走 playTrack，不重建歌单。该歌单不显示在侧栏（渲染层过滤），也不出现在「添加到歌单」的选择菜单里。旧实现是把"当前活动歌单"整单替换（replaceAllAndPlay 直接打在用户自己的歌单上），正在听的歌单内容会被顶掉 —— 这是双轨制重构修掉的最实质的一个问题。
  • 右键语义修正：queue.insertNext 的 position 默认 0（队首），queue.add / addPaths 才是追加 —— 所以「下一首播放」= insertNext(position:0)、「添加到插入队列」= add（歌单坐标）/ addPaths（路径，默认落宿主的影子歌单）。两者都不碰任何歌单；已在队列里的曲目由宿主移动而不是重复入队。
  • 播放历史（新）：事件栈 + cursor（与浏览器的后退/前进同构）—— 连续相同曲目去重、新的播放事件截断 cursor 之后的未来再追加、回溯不截断；上限默认 20（设置页「播放与队列 → 播放历史条数」可改 10/20/50/100）、localStorage 持久化。「上一首」优先回溯历史（cursor 往前找第一首不同曲目并播它，找不到才交回 playback.previous）；UI 是插队队列上方的一行「播放历史」按钮（默认收起，settings.historyOpen 记住展开状态）：点开是圆角底板面板里的只读时间线，列表由旧到新向下排、最新一条紧贴"正在播放"，整条抽屉自上而下就是「过去 → 现在 → 接下来」，双击任意一条即回到那首（jump：把 cursor 移过去再播，回溯产生的换曲不写新事件）。回溯用队列播放（queue.addPaths + moveToTop + next）实现，不写任何用户歌单；按路径集合抑制（连点两次「上一首」也不会把历史写乱）。
  • 移除试听功能：右键的「试听（不加入歌单）」与「停止试听」、页内 <audio>（media.getStreamUrl）与 JIT 无痕试听（jitQueue.playNow）整条链路删除 —— 它与正常播放是两路输出、又要靠 jitQueue:* 事件收尾，而宿主没有"播放失败"事件；core.js 的 pagePreviewActive 状态位、ui.js 的 stopPreviewIfActive、以及各调用点（歌单双击 / 播放全部 / 在线页播放 / 播放控制）里的"先停试听"包装一并清掉，原位置换成「添加到插入队列」。在线音源页的播放语义不变（仍追加进固定歌单并从新曲开播）。
  • 双击播放后的"死窗口"：renderPlaylistView 在请求在途时把 _tablePlaylist 置空，而"播放 → 触发歌单激活 → 整表重载"会让这段窗口期里的双击 / 右键被守卫静默丢掉（表现为"点完一首马上点另一首没反应"）。现在同一歌单的重载保留旧值（行还是那些行、data-index 没变），只有切歌单才置空。
  • 连点「上一首」：历史回溯的目标路径从"单个槽位"改成集合 —— 连点两次会在途重叠两条跳转链，后到的 trackChanged 不该被当新事件（否则历史被截断写乱）。
  • 设置页新增「播放与队列」组（播放历史条数）。
  • 手动 上一首 / 下一首（不需要任何 order 折腾）：下一首在插队队列非空时走宿主 queue.playNow(0)，空则由宿主的 playback.next 走 Context —— 实测宿主的 next() 在「单曲循环」档下照样换歌，所以《重构指南》里那套"临时把 order 设成 default → next → 改回"的做法没有实现（异步 IPC 下要连发三次 setPlaybackOrder，任何一次失败都会把单曲循环静默退成顺序播放，而宿主本来就是对的）。上一首优先回溯播放历史，历史到头才交回 playback.previous。
  • 宿主影子歌单不再出现在界面里：queue.addPaths（按路径插队）默认会把路径写进宿主自己的 [WebView Queue] 播放列表（官方文档：追加到专用的该播放列表，不存在则创建）—— 它跟用户歌单一样可见可编辑，但内容只是"曾经按路径插过队的曲目"，交给用户管理没有意义。现在侧栏与「添加到歌单」都隐藏它（连同主题自己的 _MediaLibraryContext_，判定集中在 CM.isInternalPlaylist），启动时"上次听歌的歌单"也不会把它自动打开。索引/guid 查找仍走完整缓存，不受影响。
  • 能交给宿主的就交给宿主：playNowPath（历史回溯 / 游离曲立即播放）改用宿主内置的 queue.playNow（"立刻播这一条队列项"，不在队首会先移到队首、播完照常出队），取代原来的 moveToTop + playback.next 两条调用 —— 顺带不再依赖"宿主的 next() 会不会先消费队列"这个没有文档保证的约定（老宿主没有该方法时自动退回过队首 + next）。队列条目的位置也不再靠"调用前查询的条数"，而是用 addPaths 回包里的 queueCount - 1，并发入队时不会提错条目。徽标则改为采信 playback:queueChanged 载荷里本来就带的 count（首次收到时与一次 queue.getCount 校准，对不上就永远退回查询），每次队列变化（含播完一首自动出队）少打一次宿主往返。
  • 历史回溯的抑制表加过期：登记"这次换曲来自回溯"的路径集合原先是永久生效的 —— 如果那次跳转根本没播起来（直链失效 / 宿主拒绝），该路径会一直留在集合里，之后用户手动播同一首时那次播放就不会被记进历史（cursor 也不跟着走）。现在条目带登记时间、30 秒未兑现即丢弃。
  • 设置页新增「高级首选项搜索」（只读工具）：foobar 的高级首选项是一棵 GUID 树，**不能按名字查询，但每一项都带显示名**（entries[].name + guid，config.getAdvancedConfigValue({guid}) 还会连名字与当前值一起回）—— 所以"遍历树 → 按显示名匹配 → 拿 guid 读值"是通的。工具支持嵌套树（一趟拿全）与逐层回包（按 parentGuid 展开，节点/展开次数都有上限）两种形状，结果列出「路径 › 名称 · 当前值 · GUID」并可一键复制。**这条顺带推翻了项目里一条旧结论**：以前认为"高级首选项只能按 GUID 读写、不认名字"，因而把"关掉 foobar 自带的播放错误提示"搁置了 —— 现在能查出那一项到底叫什么、值是多少，那个功能有解了。
  • 沉浸页右上角不再误弹贴靠布局：给宿主上报「最大化按钮矩形」时只按矩形去重，而沉浸页是 position:fixed; z-index:200、盖在标题栏（z-index:100）之上 —— DOM 里按钮还在原位，于是鼠标停在沉浸页右上角（那里是沉浸页自己的按钮）也会弹出 Win11 贴靠布局。现在每次上报前先做命中测试（elementFromPoint 落在按钮上才报），被覆盖物盖住就按 SDK 的约定省略 region 撤销区域；并用 MutationObserver 观察 body 与各覆盖物（沉浸页 / 标签编辑器 / 模态遮罩 / 右键菜单）的 class 变化即时重判。
  • 跨歌单插队不再把播放上下文带走：队列项有两种形态 —— 带歌单坐标（insertNext({items}) / queue.add，文档说坐标的意义就是"能从该歌单那条的位置继续播"）被播放时宿主会把播放上下文切到那张歌单，于是"正在播歌单 A、去歌单 B 右键下一首播放"的插队曲一播完就顺着 B 播下去了（与指南《示例 1》"插队完回 A"相反，用户实测发现）；不带坐标的裸路径/handle 项（insertNext({paths})，文档原话"新入队的裸路径没有歌单坐标"）才只是"插播这一项"。现在规则是：插队来源就是当前正在播的那张歌单 → 保留坐标（上下文不变、宿主队列标记照旧），跨歌单一律用 track.handle/绝对路径（用户实测确认：从歌单 B 插队，播完确实回到歌单 A）；唯一例外是"跨歌单 + 拿不到 handle + 明显是 CUE 子曲目"—— 裸路径指不准哪一轨，退回坐标（宁可让上下文跟过去也不播错轨）。跨歌单"追加到队尾"复用缓存的队列长度当插入位置，实测与改前的 queue.add 一样只发 1 次调用。同时 playNowPath（历史回溯 / 双击媒体库行）从 queue.addPaths 改成 insertNext({paths},0) + queue.playNow(0)：不再把路径写进 [WebView Queue] 影子歌单、也不再多一次 moveToTop。
问题修复
  • 播放顺序：宿主的 order 是序号 0..6（default / repeat-playlist / repeat-track / random / shuffle-*），不是 foobar 标志位（0/1/2/4）。此前把标志位当序号下发 —— 点「随机播放」实际设成 shuffle-tracks（会重排歌单），在 foobar 里设 Random 又读不回来、图标回落成「顺序播放」。现在一律按 name 下发、按 name 认档位，三种 shuffle 归到「随机播放」显示。
  • 换歌瞬间保存歌词会串台：loadLyrics 只清 currentLyrics，不清原文与来源 —— 在线匹配那几秒里右键「保存到文件 / 嵌入标签」会把上一首的原文写进新曲目的 .lrc / 标签，小窗也还在显示旧歌词。现在开头就把原文 / 来源清空并同步给小窗。
  • 「流派」页整页错误态：library.getGenres 是零参数方法，此前多传了 {limit} —— 插件升级到 2.0.0 后严格校验未声明键、整单拒绝，于是流派页一直报错。已去掉该参数。
  • 歌单筛选：零命中时 filterRows 是空数组，而表格用 length 判"是否处于筛选视图" → 退回渲染整张歌单（元信息却写 0 命中），现在改成 != null 并给"没有匹配的曲目"空态；筛选框的 × 也一直显示 —— hidden 属性被 CSS 的 display:flex 压过（作者样式优先于 UA 样式），已显式补 [hidden]{display:none}。
  • 「上次听歌的歌单」按名称恢复失效：CM.settings 默认对象漏了 lastPlaylist，而 loadSettings 只回填默认键 → 每次启动静默丢弃，guid 失效时的名称回退永远是 undefined。
  • 进度条禁用态是死代码：setSeekable 找的 .seekbar-wrap / .np-seekbar-wrap 都不存在（真实是 .seek-bar-wrap / .np-seek-rail），CSS 也没有 .seek-disabled —— 网络流 / 直播不可跳转时只有 title 提示。已对齐类名并补样式。
  • DPI 变化只感知一次：watchDpi 重新装监听时沿用旧查询串，第一次改缩放后再换显示器 / 改缩放都不再触发回调。
  • 同名歌单自动清理会误删：导入成功后按名字删重，只保留 index 最小的那张 —— 同名但属于用户自己的歌单（或上一次导入的内容）会被连曲目一起删。现在只清空歌单。
  • 小窗 / 托盘：小窗置顶按钮在被宿主拒绝时也点亮成「已置顶」（api() 把失败吞成 null）；关闭托盘用 CM.api，destroy 失败照样写 settings 并提示"已关闭"。都已改成失败如实反馈。
  • 设置页频谱档位少一项「矢量示波器」（共五档，此前只有四个按钮，处于该档时全不高亮）；歌词面板收起时 visibility:hidden 没过渡，面板瞬间消失而不是随轨道滑出。
  • 候选歌词面板：取词是异步的，期间切歌会把上一首的歌词渲染到新曲目上 —— 现在校验加载代际。另修 lyricReload 与 loadLyrics 的缓存键算法不一致（无艺人标签的曲目上「刷新歌词」无效）。
  • 清理：删掉「更多」菜单里已不存在的托盘行读写、无调用点的 execEslyricSearch/Reload/Script 导出、小窗未使用的 WIN_ID、频谱平滑里的空转自赋值循环。
入口重排：功能都在，但不再全塞进「更多」
  • 「更多」菜单瘦身：从 20 项 + 3 层折叠子菜单收成四段 —— 歌词 / 窗口 / 音频 / foobar2000（分区顺序沿用旧版菜单）：歌词（桌面歌词 ▸）、窗口（小窗 ▸ / 刷新界面）、音频（音频 ▸，含均衡器 / 输出设备 / 播放增益）、foobar2000（主菜单 / 设置与工具）。长内容一律折叠成组（桌面歌词 / 小窗 / 音频三组，点标题展开，默认收起）。沉浸模式改为只从底栏封面 / 右侧面板入口进（菜单里不再重复）。
  • 设置与工具页可滚动：该页是长文档，滚动容器挂在 #tabSettings 上（与「发现音乐」同一手法），此前套在 .tab-content.active 的 overflow:hidden 上、滚轮完全没反应。
  • 小窗不再随主窗口一起消失：popup 行为里的 owner 从 'main' 改为 'none' —— 官方文档里 owner:'main' 的语义是「位于主窗口之上并随主窗口最小化」，于是主窗口最小化 / 藏到托盘时小窗跟着不见了，而"主窗口让位时还能看"正是小窗存在的意义。另加 keepVisibleOnShowDesktop:true：Win+D 显示桌面时小窗也不会被收走。
  • 托盘图标：单击 / 双击都把主窗口叫回前台（右键出菜单，菜单里另有原生的「显示主窗口 / 退出」）。此前只处理了左键单击、双击无人响应。主窗口藏到托盘后它那页可能已被宿主深挂起（JS 不跑），所以小窗页也兜底处理托盘事件 —— 小窗是可见的，事件循环照常。
  • 小窗卡死能自愈：重新点「小窗」时，主窗口除了换形态与置前，还会让那个窗自己 refreshWebView + 重绘（黑屏是 WebView 表面残留的旧画面，只有该窗口自己能清）；同时发一次 ping 做存活探测，1.5 秒不应答（渲染进程已经没了）就把它关掉重开，而不是把用户丢在一个点不动的黑框前。
  • 小窗没有封面时用默认封面：和主界面同一张 static/img/no_cover.svg（CM.DEFAULT_TRACK_COVER）—— 以前小窗会把图片藏起来只留一个小音符占位，主界面是默认封面、小窗是空框，两边对不上；现在无封面、真封面加载失败（坏地址 / 文件没了）都回退到它，连默认封面都取不到才退回音符占位。封面模糊背景同样用这张图，不再留一块空背景。
  • 新增「设置与工具」页，入口是底栏「更多 → 设置与工具」（不占侧边栏）：外观与可视化（迷你频谱 / 3D 倾斜 / 频谱档位）、歌词（三源启停 + 候选列表入口）、窗口与小窗（默认形态 / 重置几何 / 常驻托盘）、foobar2000 工具（主菜单 / 首选项 / 控制台 / 刷新媒体库）、关于与帮助（版本 / 关于诊断 / 复制报告 / 指南 / 页面来源）。开关状态由 CM.syncSettingsState() 从设置与宿主回包回填，旧宿主不支持的项目（如托盘）直接置灰并写明原因。

频谱与小窗：把"接了没真正用起来"的两块磨出来

适配 2.0.0 时把 v2 的新能力都接了进来，但有两块"接了但没真正用起来"：频谱的瀑布图 / 示波器看着像坏的一样，小窗（迷你播放器 / 歌词窗）有几处交互硬伤。下面把它们逐个磨出来，没有新概念、不改布局。

频谱：瀑布图与示波器此前等于没有
  • 画布被甩出文档：沉浸页每次打开都会重建那条频谱的 DOM（innerHTML），而瀑布图 / 示波器复用同一个 <canvas> —— 重建之后它已经不在文档里，之后画的每一帧都落在一张"看不见的画布"上。表现是：第一次切过去好像有反应，退出沉浸页再进来就成了一条空槽（重启 foobar 后因为设置里记着瀑布图，一进来就是空的）。现在重建时把画布重新挂回去，并用 ResizeObserver 跟随尺寸重设位图（窗口缩放后不再糊、也不会只画到一角）。
  • 示波器改用官方接口：原来走 fb.audio.subscribeStream（实验性的共享缓冲 PCM）——宿主不给共享缓冲时既没有数据也没有报错，画布上永远只有"等待音频数据…"。改用 v2 文档里的 audio.getWaveform（signed:true 直接给 [-1, 1] 的实时波形），页面按 30fps 拉取、上一次没回来不发下一次；连续多次拿不到就说明原因并自动切回频谱条。画法也从"整幅清屏"改为轻微拖尾，更像示波器。
  • 瀑布图不再从半张黑开始：它本来是一列一列从右往左推的，刚切进来时左边一大片是空的。现在切进来 / 窗口缩放后先用当前这一帧把整幅填满，再照常滚动。
  • 沉浸页自己持有频谱订阅：订阅改为按持有者计数（底栏迷你频谱 mini、沉浸页 np）。此前只有一个全局订阅句柄，关掉底栏那个频谱开关会连带把沉浸页那条频谱一起停掉；现在最后一个持有者离开才真正退订。输出设备切换时由"重启订阅"取代原来的"停 + 起"（不会因为计数没归零而漏掉重启）。
  • 断流看门狗：播放中连续 3 秒收不到帧（输出设备切换、宿主重建可视化管线）自动重订一次；暂停 / 停止本来就不发帧（只发一帧静音帧），那种"没有帧"不会被误判。
  • 修复 binsMode 恒为 false 的小毛病：「关于」面板里的「频谱数据」一行此前永远显示"频带 (bands)"，实际用的却是原始频点。
小窗：三处交互硬伤
  • 迷你播放器的播放按钮根本点不到：.mode 给的是 flex-direction:column（歌词窗要用），#miniBody 没写回 row —— 于是在 420×150 的小窗里内容竖着堆起来，底部那排「上一首 / 播放 / 下一首」落在 y≈189–229，整排被裁在窗口外面。现在是一行三列：封面 ｜（曲名 / 歌手 / 进度 / 音量）｜ 上一首 / 播放 / 下一首；音量条挪到进度条下面，右侧那列留给按钮（最小尺寸 320×132 也不挤）。
  • 歌词窗的当前句永远不居中：自动居中的目标位置按 offsetTop 算，而歌词行的 offsetParent 是 .mode（带 position:relative）而不是滚动容器 #lyrWrap —— 目标值被整个多加了一个"封面 + 信息栏"的高度，结果永远是"能滚多少滚多少"（停在底部），当前行常常落在可视区外。现在 #lyrWrap 自己定位、目标位置按视口坐标（getBoundingClientRect）计算，当前行稳稳落在可见区正中。
  • 小窗写设置会把主窗口的设置冲掉：两个窗口共享同一份 localStorage，小窗原来是"读出整份设置 → 改一个键 → 写回"——它的旧快照会覆盖主窗口刚存下的频谱模式、音量等。现在小窗一个字节都不写：窗口几何与形态经 window.sendMessage 报给主窗口，由主窗口并进设置、下次开窗时用 createPopup 的 x / y / width / height 交回来（形态优先，切形态时也会带上 setMinSize）。
  • 尺寸单位修对（"迷你窗又小又挤、歌词显示不全"的根因）：宿主的 window.createPopup / setSize / setMinSize 收的是物理像素，而主题原来按 CSS 像素给 420×150 —— 在 140% 缩放的屏幕上那只有约 300×107 CSS 像素，组件自然挤成一团、歌词窗也被压掉一大截（window.getDpiScale / devicePixelRatio 都是 1.4 这类值）。现在尺寸一律按 CSS 像素书写、调用前乘窗口缩放比，并把当时的缩放比和几何一起记住（换显示器 / 改缩放后按比例换算回来）。默认尺寸也放宽：迷你播放器 520×168（最小 400×150）、歌词窗 460×720（最小 380×480）；歌词窗的封面从 240px 收到 168px、信息栏收紧，可视歌词行数从 4~5 行提升到 9 行左右。旧版本在错误单位下存下的几何值（比最小尺寸还小、或长宽比根本不像该形态，例如"迷你窗和竖屏一样大"）开窗时会被自动丢弃、改用新默认值；改窗口大小后当前句立即重新居中（原来只有换行时才会重算，缩放后可能停在别处）。
  • 已经开着小窗时不再开第二个：点「小窗 / 歌词窗」改为给已有窗口发 setMode 并置前（旧行为是越点越多，直到宿主的 8 个上限）。
  • 窗口行为：按 v2 的 popup behavior 设为「不进 Alt+Tab / 不许最小化」，并保留标题栏的图钉（置顶开关）；图钉状态改为开窗时向宿主读一次真实值。owner 用 'none'（独立）：'main' 的语义是"随主窗口最小化"（官方文档原话：位于主窗口之上并随主窗口最小化），主窗口进托盘时小窗会一起消失；另配 keepVisibleOnShowDesktop:true 抵抗 Win+D。
  • 封面：改由主窗口把解析好的封面（在线曲目的反查结果也在内）经 cm:art 发来并按曲目路径核对，本地曲目按路径向宿主取（artwork.getFb2kUrlByPath）；换曲先清空，不再挂着上一首的图；也不再每次播放 / 暂停都重新请求一遍（此前没有有效的缓存键）。
  • 进度：小窗打开时主动 resync() 一次时钟——暂停中的曲目没有 timeHighRes 事件，此前进度条与歌词高亮会停在 0:00 / 第一句。跨窗口的 cm:now 现在也会自己比对"是不是换了曲目"，换了就重置进度并重读位置。
  • 滚轮调音量节流：原来每个 wheel 事件 ±3（一次滚动会来十几个），轻轻一滚就顶到 0 或 100；现在"每 60ms 一步、一步 2%"。
  • 歌词跟随：自己滚动歌词后 4 秒内不再被自动居中拽回（点歌词行跳转则立即恢复跟随）；不可跳转的曲目（电台流）点歌词行会有一句反馈，不再"点了没反应"；双击封面 / 大图把主窗口叫到前面。
适配插件 2.0.0（破坏性变更修复 + 新能力落地）

为什么是 3.0.0：宿主组件升级到 2.0.0 后开始严格校验参数（未声明键、类型不符、缺必填项一律 INVALID_PARAMS 整体拒绝）。主题核心链路逐条核对过官方 v2 文档，发现 3 处调用会被拒；同时把 v2 的新能力（原始频点频谱、PlaybackClock、playlistGuid、弹窗小窗…）全部接进来，故主版本号进位。

  • 进度条 / 歌词跳转失效：playback.setPosition 的参数在 v2 是 position（旧名 seconds 会被严格校验整个拒掉）。此前表现为"拖了进度条松手回原位、点歌词行不跳、←/→ 不跳"（CM.api 把失败吞成 null，界面没有任何报错）。已修 4 处调用（底栏 + 沉浸页共用、键盘、歌词点击）。
  • 「全部歌曲」打不开：library.getAll 的分页参数在 v2 是 offset / limit（旧名 start / count 属未声明键）。表现为进入「全部歌曲」直接错误态、「添加全部到歌单」提示"加载失败"。
  • 专辑封面 / 专辑详情 / 播放专辑失效：library.getAlbumTracks 在 v2 必填 album + albumArtist（专辑行的值，逐字节比较）、不再接受 artist 与 limit。顺带优化：v2 的 library.getAlbums 行自带 firstTrackPath / firstTrackAbsolutePath，专辑封面链路改为直接用它 —— 一次省掉「每张专辑一次 getAlbumTracks」（本机 449 张专辑即 449 次宿主调用），也不再受"专辑名带引号必然查不到"的限制。专辑卡片新增 data-album-artist，播放/详情按它查询。
  • 临时歌单反复新建：playlist.getAll 的应答是 {playlists:[…]} 信封，而 ensureWritableActivePlaylist 只认裸数组 → "复用同名临时歌单"分支从不生效（这是"同名重复歌单"的来源之一）。另外 v2 的 playlist.getActive 不再返回 isAutoplaylist，"可写"判定改为以侧栏缓存的行为准、缺行时退回 isLocked。
  • 下载目录搬迁计数虚高：v2 的 file.list 同时返回 files 与 items（同一份列表的两个名字）以及 directories，旧实现把这些数组全拼起来 → 每个条目录两遍、目录被当文件搬。改为按名字去重后合并。
  • 在线获取标签（freedb）：v2 起 discovery.executeContextMenuCommand 不再回退到"正在播放 / 选中项"（无选中项时 INVALID_PARAMS），且 subGuid 不是该方法的参数。改为优先用 discovery.executeContextMenuByPath（按"父级/子级"标签路径 + trackPath 精确作用于目标曲目），失败才退回按 guid 执行。
  • SDK 1.13 → 2.0.0（缓存号 ?v=2000）：bridge.global.js 换成 2.0.0；不再加载 components.global.js 与 smp-compat.global.js（主题没有用 <fb-*> 元素、也不用 SMP API，省掉约 278KB 解析；文件仍在 sdk/ 里，需要时把 <script> 加回即可）。
新能力：频谱数据源升级 + 四种显示（都落在主题自己那一条频谱上）
  • 升级为原始 FFT 频点 + 立体声：audio.subscribeSpectrum 改用 output:'bins' + channels:'stereo' + scale:'db'（v2 新增），回调直接给 left / right 两组原始频点。由 js/audio-viz.js 按对数频率轴把频点合并成主题两处频谱条（底栏迷你 16 条、沉浸页 32 条）各自确切的条数，每条取该频段内的最大值，再交给原有的 CM.updateSpectrumBars 渲染：低频不再糊成一根、高频不再大片空白。
  • 沉浸页那一条频谱可切换五种显示（三种切换入口：右上角新增的频谱按钮点击循环切换、左键点任一条频谱循环、右键弹出菜单直接挑，当前项带 ✓；选择记进设置。按钮在非"频谱条"时点亮，一眼知道正处在别的显示上）：
    · 频谱条（默认）—— 主题原来那排频谱条，数据换成 v2 的原始频点并做了时间平滑（上升跟随、回落缓慢，不再 30fps 抖成毛刺）
    · 声场：同一排 32 条改成中缝左右分开（左半压暗一点），低频靠中缝形成蝶形 —— 左右声道的差异看得见
    · 瀑布图：在同一条 40px 槽位里用新绘制的画布替换该位置，时间 × 频率，配色取自封面强调色（--accent-h），整幅自左滚动
    · 示波器：同样替换该位置的画布，画 fb.audio.getWaveform 的实时 PCM 波形（带强调色发光）—— 早先那版走的是实验性的 fb.audio.subscribeStream，宿主不给共享缓冲时既没有数据也没有报错，已改掉
    · 矢量示波器：同一份 PCM 的左右声道当 (L, R) 坐标打点（45° 旋转的 Lissajous / 相位图）：单声道落主对角线、反相落副对角线、声像偏移整团偏向一侧 —— 与"声场"互补
  • 尺寸与布局完全不变：画布是叠在频谱条槽位里的（左右各留 8px 与频谱条对齐），频谱条用 visibility 让位而非 display，所以切换模式不产生任何重排，也不会挤动唱片/歌词那一列。退出沉浸页或关掉可视化时会主动停掉 PCM 订阅与轮询。
  • 自动回退：宿主拒绝 bin 输出、或订阅后 1.5 秒没有任何帧（没有可视化数据 / 输出设备刚切换）时，自动换回旧的频带输出重订一次 —— 任何环境下频谱都不会永久停在"全是 0"（回退模式下声场退化为对称蝶形）。
  • 性能：fftSize 8192 → 2048。旧的 8192 点 FFT 每秒算 30 次全在宿主侧，是"页面整体变卡"最可疑的一项（合并成 16/32 条之后 2048 点已绰绰有余，计算量降到 1/4）。
新能力：播放与歌单
  • 播放时钟插值（PlaybackClock + hostTime）：宿主 ~30fps 的 playback:timeHighRes 在负载高时会抖/掉帧。fb.PlaybackClock 用 hostTime 锚点 + 本地单调时钟推算两次事件之间的位置，加一条 rAF 循环（播放中且页面可见才跑，位置变化 <1/20 秒跳过）驱动进度条与歌词高亮 —— 进度条不再一跳一跳。跳转后调用 resync() 重新取锚点（宿主给的 position 已扣除输出与 DSP 延迟，不再二次补偿）。
  • 不可跳转的曲目禁用进度条：v2 的 playback.getState / stateChanged 带 canSeek，电台流/直播为 false → 两条进度条置灰并给出 tooltip，不再"拖了没反应"。
  • 歌单身份用 GUID（playlistGuid）：「上次听歌的歌单」改为优先按 guid 恢复（改名/挪位也能命中，名称留作回退）；QQ 音乐 / 网易云页的固定歌单解析顺序也改为「记忆的 guid → 名字」，创建后记下 guid。
  • 队列拖拽排序一次写完：queue.setContents（v2）用队列槽位引用 {queueIndex} 一次性重排 —— 旧的「clear + 逐项 add」在拖一次时要发 2N 次宿主调用、还会让 queueChanged 连发 N 次。槽位不全或旧宿主自动回退老路径。
  • 歌单内筛选（新）：歌单页标题下多了筛选框，查询串交给宿主的 foobar2000 查询引擎（playlist.getMatchingRows，语法与 foobar 搜索框一致：%title% HAS 晴天、artist IS 周杰伦、rating GREATER 3…），命中行号再由 playlist.getTracksAt 按需取回。行号仍是歌单真实行号，所以播放 / 右键 / 批量删除 / 调序全都不受影响；数万首的歌单也只取命中的那几首。查询被解析器拒绝时如实提示（INVALID_PARAMS + details.param='query'）。
  • 页内试听（新，media.getStreamUrl）：本地曲目的「试听」优先走 media.getStreamUrl + 页面自己的 <audio> —— 不占用 foobar2000 的输出，试听时正在播的歌不会被切掉；宿主不给流地址（在线直链 / 容器不支持）或自动播放被拒时自动回退原来的 JIT 无痕试听。
新能力：小窗、歌词与标签
  • 小窗页面（新，两种形态）：歌词面板右键，或底栏「更多 → 窗口 → 小窗」里的「迷你播放器 / 歌词窗」打开（v2 的 window.createPopup，无边框置顶）。
    · 迷你播放器小窗（默认 520×168，最小 400×150）：封面 + 曲名/歌手 + 进度条 + 音量 + 上一首/播放/下一首；滚轮也能调音量。
    · 歌词窗（竖版）（默认 460×720，最小 380×480）：上是大封面，封面下方小字歌曲信息（曲名 + 艺术家 · 专辑），中间是整首可滚动的歌词（当前行放大高亮 + 柔和发光 + 自动居中，点任意一行跳到该句），底部是进度条与上一首/播放/下一首；封面、信息与歌词对齐在同一条中轴上。
    两个形态是同一个页面，切换用 v2 的 window.setSize 现场换尺寸（不重建窗口），位置与尺寸按形态记在共享存储里（下次开窗沿用）。样式与主界面同一套：直接加载主主题的 css/variables.css（--bg-* / --text-* / --r-* / --ease 等令牌一致），跟随封面取色（主窗口把 --accent-h/s/l 经 fb.sharedState 的 cm:theme 发来），并用封面做模糊背景。曲名/歌手/歌词从跨窗口状态（cm:now / cm:lyrics）取 —— 匹配、编码检测、双语归组、逐字切分全部由主窗口做完，小窗只渲染，不会重复联网、也不必加载桥接模块。
  • 歌词兜底与保存：本地链路在「同名 .lrc / 歌词库」之后新增一档 lyrics.get（v2）—— 覆盖内嵌在标签里的歌词与宿主认识的其他旁挂文件名，取回的文本仍走主题自己的编码检测与解析（顺带受益：v2 修掉了「LYRICIST 标签被当成歌词读取」）。歌词右键菜单新增「保存歌词到文件」与「嵌入到歌曲标签」（lyrics.save，原文照写不重排不改字；整轨 / CUE 子曲目因 v2 需显式 filename，明确提示到 foobar 手动保存）。
